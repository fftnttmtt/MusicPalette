# 按小节预测情绪：自适应上下文版

## 修复未知和弦X导致的KeyError

和弦识别器允许输出X，但固定版本的chord_root.json只有N和十二个根音，没有X。
旧推理代码先查chordRootDic['X']才判断特殊标签，因此部分输入会报KeyError: 'X'。
已按官方新版HuggingFace推理代码的兼容方式修正：X的根音编码采用N占位、属性编码为0，
整和弦编码仍保留X；其他合法和弦的编码不变，不猜测具体和弦、不跳过整段音乐。
修正通过backend.py对固定版本的推理代码适配生效，无需更换权重或重装环境。

raw_prediction.status=skipped_minimum仅表示未扩展目标段不足3秒，因此未做原始段对比；
正式情绪预测使用扩展上下文，仍满足至少3秒要求。forced_boundary_crossings=[]表示没有强制跨强边界。
单段推理异常现在会在完整JSON/CSV保留error_type和error_traceback，并可在界面“本段详细错误”中查看。
覆盖代码并关闭旧程序、重启start.bat后，重新预测曾失败的音乐。

## 可选逐节拍预测

侧栏新增“按节拍预测（较慢）”开关，默认关闭，继续按小节预测；开启后按钮切换为“逐节拍预测”。
使用Beat This!检测到的相邻节拍作为目标边界，不按固定时长或假定BPM均匀分拍。
保留第一拍之前和最后一拍至音频结束的区间，超长节拍区间仍先按a秒上限切分。
上下文算法保持不变：默认预测目标总时长a=6秒，至少3秒，强边界阈值0.7，Foote参数不变。
逐拍提高的是目标时间网格分辨率，模型仍读取扩展上下文，因此相邻拍的预测可能相近；目标短于3秒时不运行未扩展对比。
每个不同的实际预测窗口独立推理，完全相同的窗口复用缓存；整曲仍只预测一次。

第一小节前不足1秒时，逐拍模式让前奏区间沿用第一小节首拍的结果（该小节起点也须是检测拍点），保留原始节拍位置。
缺少可用节拍时明确提示，不生成假拍点，保留音频并按a秒上限回退预测。
CSV/JSON保存prediction_unit=beat、beat_number、beat_in_bar及所属小节编号与范围；Beat This!原始小节信息仍保留。
预览、标签热力图、颜色条、播放器及连续颜色CSV均使用实际目标段起点，逐拍时准确对齐节拍。
颜色算法保持一致，最大过渡占比默认15%，Hγ=2；节拍模式按相邻节拍起点间隔计算过渡长度，结束时刻仍固定在下一拍。
整曲色彩标签的映射独立于小节/节拍选择。切换开关后需要重新预览或预测，旧小节结果不会自动变成逐拍结果。
命令行可加入--per-beat开启，例如：

```bat
.venv\Scripts\python.exe analyze_bars.py "D:\Music\song.mp3" --per-beat --output beat_emotions.json
```

## 整曲标签核查修正

整曲色彩标签现在使用独立的整曲映射统计，不再受已分析小节的VA分布、选段范围或切分数量影响。
原来将小节分位数和均值中心用于整曲VA，会让同一整曲预测值在分析不同片段时得到不同S/V，现已修正。
全曲只有一组全局VA，按同一增强规则其分布为常量，因此相对拉伸自动为恒等变换。
开启自动敏感中心时使用整曲VA本身归一化后的值；关闭后使用手动中心。
全曲仍使用当前的九标签、H/S/V伽马、Sigmoid斜率和输出范围。小节自身的增强不受影响。
颜色JSON单独保存whole_song_mapping；独立整曲标签JSON中的mapping也改为真正的整曲映射上下文。

MERT仍覆盖完整音频，但分段特征改为按实际采样数加权，避免不足30秒的尾段获得完整段同等权重。
例如65秒音频按30+30+5秒处理时，权重从各1/3改为30/65、30/65、5/65。
相同长度的完整段权重相同，单段小节输入保持原特征；原模型和声分支最多100个和弦事件的架构限制保留。
新增“核查整曲预测与色相权重”，显示实际输入范围、原始VA、九标签得分、实际色相权重与独立映射参数。
新预测带有inference_pipeline_version=duration_weighted_mert_v1。旧结果可以重新映射修正S/V，
但MERT尾段加权需要重新运行模型才能更新标签得分和VA。

## energetic色相与九标签

新增energetic（活力充沛），色相H=10°。它与原有八个启用标签共同参与小节和整曲的色相预测、最高分回退及热力图。

模型本身已经输出energetic；导入包含完整标签得分的旧预测JSON即可重新映射，无需重新运行模型。

## 不足1秒的开头片段与整曲色彩标签

第一小节前的开头片段严格小于1秒时，不再单独送入模型；其实际输入范围和情绪结果均采用第一小节的。
保留开头音频及原时间范围，时间轴从开头即呈现第一小节颜色，不移动第一小节起点。
恰好1秒或更长的开头片段仍独立预测；没有检测出完整小节时不虚构可继承的结果。
若第一小节超过a秒而被切分，开头采用该小节第一个子段的结果。
范围表及CSV/JSON记录prediction_source、inherited_from_segment、independent_prediction_skipped；
继承片段不计算独立的未扩展对比，raw_prediction.status为skipped_inherited。

点击“逐小节预测”后，还将完整上传音频作为单独输入交给同一Music2Emo模型，生成whole_song_prediction。
即使侧边栏只选择部分小节分析，整曲预测也覆盖从0秒到音乐结尾；整曲输入不受a秒上限限制。
模型沿用已有的整曲特征提取流程（MERT按30秒处理，包含尾部），不是将小节预测或颜色求平均。
如整曲输入和某个已预测输入完全相同则复用缓存。整曲失败会单独提示，不丢弃成功的小节结果。

页面顶部新增“整曲色彩标签”，显示色块、HEX、HSV及整曲VA，并支持单独下载song_color_label.json。
整曲颜色使用当前相同的九标签全有效得分色相规则、零权重回退、S/V增强、Sigmoid、Gamma及输出范围。
整曲自动中心和增强参照只使用独立整曲预测；整曲预测也不加入小节统计，避免相互影响。
调整颜色参数时，整曲色彩标签同步更新，无需重新推理。颜色JSON包含whole_song_color，完整结果JSON包含整曲预测。
旧完整结果JSON仍可显示时间轴，但需要重新预测以补充整曲标签和新的前奏继承结果。

## 超长小节强制切分

a同时是目标段的最长时长及预测上下文的目标总时长，默认6秒，至少3秒。
Beat This!识别后，凡超过a秒的小节或首尾/未检测区间，先切成多个不超过a秒的实际目标段。
分割数量取满足上限的最少段数，尽量均衡各段长度，优先选择可行的检测拍位置；没有合适拍点时按采样点切分。
例如13秒原始小节、a=6秒时，可能在检测拍上分成4+5+4秒，而非6+6+1秒。
不移动原始小节边界，不丢失、重复或补零目标音频。样本上限为floor(a×sr)，因此目标段严格不长于a。
不足3秒的子段仍通过邻近上下文满足模型输入下限，输入不超过a秒；达到3秒后仍尊重强边界。

实际目标段重新连续编号，保留bar_number、source_segment_index、source_kind和原始起止时间。
forced_split、split_part、split_count、split_start_reason标明强制切分与具体落点。
范围表、预测CSV/JSON和目标音频ZIP均使用切分后的目标段；beat_analysis保留Beat This!原始识别结果用于核对。
颜色在实际目标段起点对齐，原始小节起点仍保留，新增子段起点也成为颜色节点。
这项修改涉及新增音频段，需要重新预览并预测；导入旧预测JSON不会凭空生成新增子段的情绪预测。

## S/V歌曲内自适应增强

默认开启，使用按原始目标片段时长加权的P10–P90范围；增强强度0.5，最大放大5倍。
默认H的γ=2，标签权重为p²；S/V的γ均为1（不改变输入），S/V的Sigmoid斜率k=0（线性恒等映射）。歌曲均值中心开关保留，k=0时中心不影响输出。
输出范围默认S=[0.2,1]、V=[0.25,1]，使低饱和度及暗段仍保留可见颜色；均可调整。

在“S/V变化增强”中可调整开关、强度、两个分位点、放大上限及S/V输出范围。
先将VA按(x−1)/8归一化，分别计算arousal与valence的时长加权分位数low/high。
有效跨度w=max(high−low,1/max_gain)，以(low+high)/2为中心构造有效上下界。
relative=clip((x−lower_bound)/w,0,1)，z=(1−strength)*x+strength*relative。
再用z计算归一化Sigmoid、各自Gamma，最后线性缩放至输出范围。
只放大相对于歌曲内部的变化，不改变标签得分或H；不同歌曲的同一S/V未必代表相同绝对情绪。

强度0恢复原始输入尺度，强度1完全使用相对范围；最大增益限制微小噪声被扩展成全范围。
整首恒定的维度不作自适应拉伸。失败段和无效VA不参与统计；部分分析仅使用已分析范围。
统计使用原始目标时长，不使用重叠预测窗时长；分位数采用加权经验分布的逆CDF。
自动Sigmoid中心是原始时长加权均值经同样归一化和增强后的值，界面显示最终实际中心。
手动中心直接作用于增强后的尺度。关闭增强开关同时恢复S/V输出范围至[0,1]。

无需重新预测，可导入旧完整结果JSON。播放器、连续色条与所有颜色导出统一应用增强。
颜色JSON保存统计范围、增益上限、混合强度、有效中心和输出范围；
片段CSV增加adapted_arousal/valence以及Gamma后的中间值，便于复现和对照。

## 禁用funny的独立版本

本版本完全禁用funny：不参与色相加权、低分回退、标签排名、热力图、有效标签列表及得分CSV导出。
仅使用calm、romantic、dream、sad、epic、happy、love、nature、energetic九个指定标签映射色相。
即使funny得分最高，也不会影响颜色。旧完整结果JSON（包括funny减0.1版）导入后同样禁用。
模型内部仍按原始56维输出推理，标签与权重对应关系不变；结果保留其余55个标签，得分不重新归一化。

九标签的所有有效得分均参与加权，低于0.3仍生效。仅在全部权重为0时采用最高分有效标签的色相。
缺失、非有限或超出0–1的分数不参与；并列时按预设九标签顺序选择，全为0时也按此顺序。
没有任何有效标签、预测失败或正常加权向量完全抵消时仍显示未映射。
原先的funny减0.1版本作为独立程序保留。

## 边界持色过渡（默认）与原指数渐变

默认S斜率k=0、V斜率k=0，H的γ=2，S/V的γ均为1；S/V的Sigmoid和Gamma默认不改变输入。
“颜色过渡”中默认开启“边界持色过渡”：每个原始小节起点是该小节预测颜色的固定节点。
渐变在相邻小节起点之间进行，到下一个起点时准确达到下一小节颜色，随后持色或开始下一段渐变。
原小节起止时间、音频时间轴和颜色节点均不平移；已修复旧版从边界才开始换色造成的滞后。
已移除“过渡时长范围”控件及固定秒数上下限，时长直接由相邻颜色节点间隔与Foote强度决定。
响应强度k默认8，可调0–10。边界比较半径默认0.25秒，可调0–1秒，
实际比较范围不超过相邻较短小节的一半，默认取该范围Foote的时间加权平均值n并截到0–1，减少孤立峰值把所有过渡压短的问题。
可切换“局部峰值”作比较；诊断同时记录novelty_mean和novelty_peak。

设相邻小节起点间隔为L，过渡时长d=L×[1−expm1(k×n)/expm1(k)]；k=0时为d=L×(1−n)。
因此n=0时可用满两个起点之间的间隔，n=1时在边界直接切色；k越大，越集中在强变化处缩短过渡。
默认k=8时，4秒起点间隔在n=0/0.5/1时，请求过渡时长分别为4秒、约3.928秒和0秒。
零时长按直接切色处理，播放器和导出不会除零；SVG边界采用单侧极限，避免显示成提前渐变。
实际时长=min(d,相邻小节起点间隔×最大占比)，最大占比默认15%，界面可调10–100%。
过渡结束=下一小节原始起点，过渡开始=过渡结束−实际时长，且始终位于两个起点之间，连续过渡不会重叠。
默认过渡最多使用两个节点间15%的时长，在每个起点后留出持色区间；调整最大占比不会改变到达下一个颜色节点的时刻。
换色期间以smoothstep进度在OKLab内插值，持色期间保持端点色。
缺少Foote时使用相邻起点间隔并遵守最大占比；失败片段和未分析空隙不跨越插值。
界面直接显示实际时长的最短值、中位数、最长值及受节点间隔限制的次数。
“查看边界与实际过渡时长”表保存各边界的平均/峰值Foote、起止位置、请求与实际时长及裁剪标记。

可以切换到“原指数连续渐变”作试听比较。此模式沿用参考app(2).py所调用的palette_core.acoustic_interpolate方案：

- 同样以每个原始目标片段起点为固定颜色节点；先按HSV规则生成节点颜色，再转换为OKLab插值。
- 速度场r(t)=0.2+expm1(clip(强度×clip(Foote变化,0,3),0,20))。
- 速度在Foote特征网格与颜色节点的并集上定义；对分段线性速度精确积分，
  在相邻颜色节点间归一化累计进度，再作smoothstep(u)=u²(3−2u)。
- 因此强变化处承担更多颜色变化，弱变化处更缓慢；速度由当前音频的Foote变化强度决定，
  不是对Foote曲线求时间导数。过渡不依赖播放帧率或导出采样网格。
- 首个节点之前与最后节点之后保持端点色，失败片段及未分析空隙不插值。
- 部分分析会给Foote相对时间加上分析起点，与原音频绝对时间一致。

大颜色块与播放器小色条、SVG使用同一条曲线。大色块每帧按音频currentTime计算，
暂停保留颜色，拖动立即更新；不使用独立计时器或CSS动画。
静态SVG以约1800个基础采样点加每次边界过渡的17个点近似显示渐变，明确保留持色区间；实时播放器直接计算当前颜色。
原HSV/HEX CSV仍为每个目标片段的预测颜色；连续CSV使用30点/秒基础网格，并额外插入所有原始小节起点、终点及渐变端点，保留原始时间精度，避免采样网格造成对齐误差。
颜色JSON保存所选模式、响应参数和完整过渡数据：边界模式保存事件时长与Foote值，原模式保存速度网格和积分，便于复现。
过渡色的HSV是插值后RGB换算值；节点的S/V仍严格遵循所选Sigmoid和Gamma参数。
关闭“启用颜色过渡”可返回逐片段直接切色。旧完整结果JSON含diagnostic曲线即可直接使用，无需重新运行情绪模型。
缺少有效曲线时，边界模式按相邻起点间隔计算，原指数模式退回普通平滑渐变，界面均注明。

## 歌曲均值敏感中心开关

展开“Sigmoid映射参数”，可调整“用歌曲均值作为 S/V 敏感中心”。默认开启。
S中心 = clip((arousal时长加权均值−1)/8,0,1)，V中心 = clip((valence时长加权均值−1)/8,0,1)。
均值使用成功、情绪值有效的原始目标片段，以片段时长为权重，不用重叠扩展段时长。
即使某片段的H因标签缺失或向量抵消无法映射，只要VA有效，仍参与均值。
均值覆盖当前已有结果；若仅分析歌曲一部分，只能得到已分析范围均值，界面注明范围。
没有有效预测时开关禁用；关闭开关恢复之前的手动中心。斜率与三组gamma不变。
调整不重新推理；颜色JSON保存均值、有效时长、自动模式和最终实际使用的中心。

## 独立伽马变换

H、S、V各有一个独立伽马指数，默认Hγ=2、Sγ=Vγ=1，界面可调0.1–5。
统一采用 y=x^γ，绝非 x^(1/γ)。

- S：arousal归一化 → 自适应增强 → 归一化Sigmoid → S₀^γS → S输出范围。
- V：valence归一化 → 自适应增强 → 归一化Sigmoid → V₀^γV → V输出范围。
- H：funny禁用，使用九个指定标签的全部有效得分，以w=p^γH作圆周加权平均；权重全为0时取最高分有效标签色相。
- H没有对色相角作幂变换。修正后得分0.3在γH=2时权重为0.09，仍然保留。
- γH>1强调高分标签，0<γH<1减小已保留标签之间的权重差异。
- S/V的γ>1降低饱和度/明度，γ<1提高，γ=1保持原结果。

只重算颜色，无需情绪推理；颜色条、播放色块及导出统一使用最终HSV。
JSON保存三个γ以及实际伽马权重，CSV还保存S/V伽马前的值以便对照。

## 可调归一化 Sigmoid

在“Sigmoid映射参数”中分别设置S和V的斜率k与敏感中心c。默认k=0，使该步骤为恒等映射；提高k后敏感中心参数才会影响输出。
输入x是情绪值1–9归一化后的0–1值；x=0.5对应原始情绪值5。

f(x;k,c) = [σ(k(x−c))−σ(−kc)] / [σ(k(1−c))−σ(−kc)]，σ(z)=1/(1+exp(−z))。

归一化保证0映射到0、1映射到1。手动c=0.5时中点仍映射到0.5，k越大中点附近越敏感。
k可调0–40，k=0采用极限形式f(x)=x（线性）；中心可调0–1。
调整颜色参数不重新运行情绪模型，颜色条、播放色块和导出使用同一组映射参数。
颜色JSON包含参数与各段实际参与色相平均的标签，CSV包含参与标签列表。
侧栏的标签显示阈值只影响标签文字显示，不影响色相计算；色相不再筛除低于0.3的得分，热力图显示全部有效得分。

无需重新预测：可直接导入此前下载的完整结果JSON。支持下载颜色条SVG、颜色CSV与JSON。

- xV = clip((valence - 1) / 8, 0, 1)，V = Vmin+(Vmax−Vmin)*f(adapt(xV); kV,cV)^γV。

## 扩展规则

Beat This! 下拍划定小节，首尾未完整的小节片段单独标记并保留。
全曲一次性计算MFCC、色度、能量特征与Foote novelty，权重0.45/0.35/0.20。
在Foote声学特征时间网格上逐步扩展，最后一步按采样点截到所需总时长；比较左右新增区间的平均novelty加0.5倍最大峰值；
优先向变化较小的一侧扩展，同分时选择借入上下文较少的一侧。
强边界阈值默认0.7，Foote比较上下文默认2秒，均可调。
检测节拍仍用于划分原始小节与记录实际输入拍数，不用于判断是否达到扩展目标；没有检测拍时也按秒扩展，不伪造拍数。

- 输入不足3秒：强制扩展，即使跨过强边界；标记 forced_expansion 和具体跨越范围。
- 达到3秒以后：强边界阻止继续向该侧扩展。两侧都阻挡可在达到a秒前结束。
- 超长原始小节先强制切分，每个实际目标段最多floor(a×sr)个采样点；保留来源小节编号与原始端点。
- 上下文达到floor(a×sr)个采样点后停止，不超过a秒；允许在拍内部截取。a不能小于3秒。
- 边缘只有一侧有音频时向可用侧扩展；全曲不足3秒则拒绝预测，不补静音、不循环。

预测上下文允许重叠，目标段完整覆盖原音频且不重叠；时间轴和目标音频按实际目标段区间显示。
未扩展目标段至少3秒时可单独预测并与上下文结果比较；不足3秒明确跳过未扩展预测。
同一任务中相同输入区间复用推理结果；未对相邻小节预测做额外平滑。

### 怎么看分数

- **标签分数**：模型56个独立 sigmoid 分数，是各标签出现的预测分数，不是各情感的成分占比，不强制总和为1。没有额外概率校准。
- **阈值**：默认0.5，仅控制显示哪些标签。调低阈值可以观察弱标签，不改变模型输出，也不重新推理。
- **Valence**：情绪效价，低值偏消极，高值偏积极。
- **Arousal**：唤醒度，低值偏平静，高值偏激动。
- VA训练标注尺度是1～9；回归分支未硬性限制输出，时间轴与表格显示原始预测数值。
- 页面结果对应表格中的每个声学分段；更改分段参数后需重新点击“分段并预测”。
- 1秒段可以提取特征，但短片段、静音、无明显和声内容的情绪预测可能不稳定。可以增大最短段长，比较效果。
- 新版网页逐段预测，不再将所有声学分段汇总成一个全曲结果；每段内部仍使用官方模型的特征聚合。
- 第一次耗时包括模型加载/音频特征计算，之后缓存模型。CPU较慢，实际耗时取决于硬件和音乐长度。

- 解码失败：先用播放器/音频工具导出WAV，再上传；M4A/AAC不在这个测试包的上传列表中。
- CUDA不可用：在网页选择CPU，或检查NVIDIA驱动和GPU版PyTorch。
- 内存/显存不足：减少分析时长，例如30秒，并关闭其他占内存程序。
- 安装中断或网络错误：重新运行对应安装脚本，或逐个手动下载权重。把完整错误发回来便于排查。
- 8501端口占用：编辑启动脚本，将 `--server.port 8501` 改为8502。

## 6. 代码来源与修正

Music2Emo 推理代码固定到 `b036e59471583c3d5b30c69e63e8c7323cc36c4a`；
MERT代码/配置固定到 `12af15fef9d0ac838c3f475bfbbf26d2060dd4f5`。

测试器沿用官方 MERT第5/6索引层特征、和弦提取、调性分析和情绪网络，通过forward hook保留全部56个原始分类logit再计算sigmoid。

为便于本地运行，包含这些明确修正：

1. 本地MERT加载及CPU/CUDA选择；和弦权重加载显式指定设备。
2. 去掉未使用的Gradio及训练专用Lightning导入，避免为推理安装整套训练依赖。
3. 官方CQT代码对≤10秒音频可能引用未初始化变量，改为先收集片段再合并。
4. 官方调性模式读取会从已裁成主音的字符串中读取大小调；这里使用此前已解析的key_type。
5. 保留MERT最后一个不足30秒的片段；不足3秒的尾部合并入上一片段，CQT极短尾部同样合并。
6. 使用推理模式及MERT eval模式。
7. 将旧版mir_eval 0.7升级到0.8.2，修复和弦编码对已移除NumPy别名np.int的访问；验证全部170种和弦输出标签及音级旋转。

因此少数输入的结果可能与原始线上Demo存在差异，尤其是小调和包含不满30秒尾部的音频。没有重新训练或修改权重。
