# SPECTRA · 本机预测接入版

## 启动

1. 本 R32 压缩包内直接是项目文件，不再套一层目录。将其直接解压覆盖到原来的 `music2emo_test` 根目录，使 `start_spectra_fixed.bat` 与现有 `.venv` 在同一级。保留现有虚拟环境和模型权重。
2. 双击 **start_spectra_fixed.bat**，使用它新打开的页面。默认端口 8765，若被旧实例占用会自动改用空闲端口，不终止旧实例。在设置的“泡泡运动”中应看到“本地修复版 R32 · epic 双框净间距 3 px”。
3. 点击原来的“选择音乐”，等待本机 CUDA 预测完成后播放。原来的播放、进度条、全屏、频谱和泡泡运动设置继续使用。相近峰间距默认 2，图形尺寸默认 150%。频谱和拍点对照音默认开启，可分别在页面和设置中关闭。图形尺寸只由“图形尺寸”控制，允许重叠；“相近峰间距 x”只控制选峰密度，不限制图形大小。

默认按小节预测。设置面板中的“按节拍预测”开关默认关闭；更改后重新选择音乐生效。CUDA 自检或内核报错仍使用项目已有的 `repair_cuda.bat`，没有静默切到 CPU。首次使用 final0 时，如本机没有缓存，会按原有下载流程获取权重。

关闭终端停止服务。端口冲突时，在项目目录运行 `.venv\Scripts\python.exe spectra_server.py --port 8766`。Linux/macOS 使用 `.venv/bin/python spectra_server.py`。

## 在线版和已有结果

在线地址：<https://spectral-forms.abloomdegu.chatgpt.site/>

在线版先选择同一份音乐，再在设置中点击“导入预测 JSON”。预测在本机完成，在线版读取结果进行播放与可视化。

- 本机 SPECTRA 分析完后，设置中的“导出预测 JSON”生成 `*.spectra.json`。
- 原 Streamlit 程序仍用 `start.bat` 启动，结果面板新增“导出 SPECTRA 预测 JSON（当前默认配色）”。这个按钮使用当前默认颜色参数，不使用面板上临时调过的配色参数。
- 旧版完整预测 JSON 无需重新推理，可转换：

```bat
.venv\Scripts\python.exe spectra_server.py --convert result.json
```

生成 `result.spectra.json`。输入必须包含 `beat_analysis`、`segments`、采样率等完整结果；单独的颜色 JSON、tag 分数或节拍 JSON 无法还原所有信息。

导入时核对音频时长；结果带有原文件 SHA-256 时，同时核对文件内容。请使用同一份音频文件。试听示例保留单独的示例标识，不充当实际音乐的预测。

## 图形分配

每个原始小节中实际新生成的 N 个图形，对九个有效 tag 的得分分别做 γ=2 变换（score²），再按变换后的权重比例，用最大余数法分配整数数量，然后随机打乱出生位置。例如 happy=0.5、love=0.25，权重比例变成 4:1；N=5 时分成 4 个 happy、1 个 love。

每个 tag 先独立平方，再合并同形标签的权重：calm²+nature²、romantic²+love²。所有有效正分数参与计算，funny 完全排除。图形配额 γ 固定为 2。

| Tag | 主体 | 描边 |
| --- | --- | --- |
| calm / nature | 绿色圆 | 蓝色单线 |
| romantic / love | 红色圆 | 粉色单线 |
| dream | 白色圆 | 黄色单线 |
| sad | 蓝色向下三角 | 灰色单线 |
| epic | 黄色向上三角 | 蓝色双线 |
| happy | 黄色圆 | 橙色双线 |
| energetic | 橙色圆 | 黄色单线 |

图形仍由原频谱上升率和拍点短窗决定何时出生、数量和横向位置；图形横坐标固定在出生位置，只做纵向升降；换绑仅影响频谱监测，不再移动图形。刷新、保留和淡出规则保留。分配随机种子固定，因此同一结果、相同窗口尺寸和设置下，重播与拖动进度不会重新抽取图形。图形保留其出生小节的样式，不在延续到下一个小节时突然变形。逐拍预测或超长小节被强制分割时，先按原目标区间与原小节的重叠时长汇总 tag，再分配图形，不使用扩展上下文的起点来归属小节。

## 使用的预测默认值

CUDA、Beat This! final0、默认按小节；目标总预测时长 a=6 秒，模型最短输入 3 秒；强边界阈值 0.7，Foote 比较上下文 2 秒。超过 a 的目标段先切分；第一小节前不足 1 秒的片段沿用第一小节预测。保留未扩展目标段的对照预测。

Hγ=2，Sγ=Vγ=1；S/V Sigmoid k=0，均值敏感中心开启；S/V 自适应增强强度 0.5，P10/P90、最大增益 5，S 输出 [0.2,1]、V 输出 [0.25,1]。九个 tag 的有效分数全部参与色相圆周加权。

Foote 过渡开启，响应强度 8，边界半径 0.25 秒，取局部均值。过渡从新片段的原始起点开始，最多占接收片段起点间隔（末段取剩余时长）的 15%，不再在前一个小节中提前混入下一小节颜色。旧 SPECTRA JSON 导入时自动升级过渡时序，无需重新预测。画面使用 AudioContext 输出时间戳补偿音频输出延迟；不支持时按设备报告的 baseLatency 和 outputLatency 回退，拍点时间戳保持不变。暂停、跳转、自然结束均按此时钟处理。右上角色点来自整曲独立预测，悬停可查看整曲颜色值。

## 验证范围

107 项 Python 测试与 55 项页面逻辑测试通过，包括现有分段和颜色算法、配额分配、随机稳定性、原始边界同步、跨语言配色一致性、本地音频上传、任务状态与前端接线。页面逻辑测试使用 DOM/音频桩，不是浏览器截图测试。交付环境缺少完整模型权重和 CUDA，未运行真实 GPU 推理，也未进行浏览器画面验收。

曲末退场：持续到音乐结束的图形会继续按当前质量与淡出参数下落、淡出至消失，进度条保持曲末；普通暂停仍冻结画面。所有几何形描边线宽由 1.6 px 调为 4.8 px（原来的三倍），单线/双线数量不变。

最高点微悬浮：泡泡运动设置中的“悬浮强度”范围 0%–500%，默认 400%；0% 关闭浮动，100% 对应原始的 2–4 px 幅度。拖动即时生效，无需重算频谱。到达最高点后，用 0.3 秒逐渐引入纵向浮动，按实际音频播放时间每 2–4 秒完成一轮（不随长拍放慢）；每个图形使用固定随机相位、周期和幅度。横向仍固定；逐拍缩放单独跟随实际拍点。浮动随淡出平滑减弱，不会先跳回原位置。音乐暂停则浮动暂停，跳转与重播可还原同一状态；曲末退场继续生效。

拍点显现修正：视觉不透明度与升起运动分开。图形到原始拍点时先以 35% 不透明度出现，再按基准淡入时长达到完全可见（默认 180 ms），质量不再拖慢显现；升起仍受质量影响，默认质量 8 的升起时长约 509 ms。开播或跳转时，在音频输出时钟达到实际播放起点前不显示新图形。节拍数据没有整体平移。

节拍设置新增“拍点对照音”，默认关闭；点击声按同一拍点数组、同一音频时钟调度。点击声若与音乐也不合拍，应检查模型拍点本身。不是每一拍都一定新生图形：频谱阈值、相近峰筛选、已有图形的保留/刷新仍生效。

空间与保持渐淡：图形出生中心的纵坐标按原强度顺序，从原约 21%–50% 高度带展开到 18%–86%；频谱本身的布局不变。到达最高点后，约 4 拍内逐渐降低不透明度至 25%，随后保持这个存在感下限，退场仍淡出到零。此渐淡仅作用于显示，不影响升降与悬浮；暂停与跳转仍由音乐时间确定。

位置 γ 默认 0.5，可在“泡泡运动”中调整（0.1–2）；1 恢复线性分布。小于 1 时拉开低强度区域的纵向差异，保持强弱顺序。仅改变纵向出生位置，实时生效，无需重新预测，也不重建事件；拍点、透明度、升降和悬浮保持原有节奏。此参数独立于颜色和图形配额 γ。

逐拍呼吸与尾部清屏：持续超过一拍的几何形，从后续实际拍点开始，每拍一次轻微膨胀收缩，最大放大 5%，一次约 180–220 ms（快节奏按拍间距缩短），出生拍不额外缩放。音频输出时钟驱动，暂停冻结、跳转可还原。默认显示频谱、开启拍点对照音。尾部静音阈值默认 -50 dBFS，设置中可调 -70 至 -25 dBFS；按各声道独立测量的 20 ms RMS 判断，避免立体声相位抵消。只在后续再无超过阈值声音的终末静音持续 150 ms 后，图形从当前的位置与透明度开始正常下落淡出，完成后清空，曲中休止不触发。尾部节拍音同步截止；原音乐播放和背景色保持。跳回静音前可正常恢复图形，无需重新预测。

尾部退场沿用每个图形的质量、升降幅度和基准淡出时长，默认质量 8、基准淡出 180 ms 时实际约 509 ms；已经在下落的图形继续原有动作，不重新计时。退场阶段悬浮平滑减弱，未来的图形出生被抑制；原始事件保持不变，因此拖回前面可恢复。同一音频时间的退场可还原，暂停冻结，短尾部跨越文件结束时仍可完成下落淡出。

双线三角形描边修正：按三角形平行边的垂直距离计算外圈间距，补偿内切半径只有外接半径一半的几何关系；线宽仍为 4.8 px，最小图形尺寸时两条描边之间也至少留 3 px 净空隙。主体三角形尺寸保持，单线三角形与圆形布局保持。

epic 朝上双线三角形进一步修正：改用两个独立的空心三角形色带（evenodd 填充），每条边框垂直厚度仍为 4.8 px，两框之间净空固定为 50 CSS px。避免依赖 stroke 接角；黄主体和蓝边框颜色保持。实际绘制路径经 Cairo 栅格化后，在此前 8 px 版本的默认 150% 与最小 55% 尺寸下蓝边框均是两个互不连接的闭环；此检查不等同浏览器实景验收。向下三角形与圆形保留原有绘制。

epic 当前间距：两个蓝色边框之间的垂直净空固定为 50 CSS 像素（不含 4.8 px 线宽），不随尺寸或逐拍缩放改变。55 项逻辑测试覆盖最小、默认、最大尺寸以及逐拍放大状态下的精确净间距。
